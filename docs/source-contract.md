# 来源格式与业务语义

## 支持范围（本地限定）

采集器 `collector.py` 仅在以下 GRIB2 模板内做实际数据采集，超出范围的**场**被拒绝并记录原因，同消息后续场与后续消息仍可检查：

- 第 3 段网格定义模板 **3.0 规则经纬网**（latitude/longitude）；
- 第 4 段产品定义模板 **4.0 确定性预报**（analysis or forecast at a horizontal level）；
- 第 5 段数据表示模板 **5.0 simple packing**；
- 第 6 段位图指示符：`0` 本段显式位图、`255` 无位图（全有效）、`254` 复用同消息先前位图。

不支持 JPEG2000、复谱、复杂打包、相邻经线交替扫描（扫描模式 bit3）、随格点附加坐标值等；遇到不支持的网格/产品/表示模板或位图指示符，拒绝该场而非用其他模板硬解。

## 两个计数概念

- **网格总点数**来自第 3 段 `Ni*Nj`（与段内格点总数字段交叉校验），是格点索引空间的大小；
- **打包值个数**来自第 5 段，只等于位图中有效点（位=1）的数量，可少于网格总点数。

绝不能把打包值个数当作网格总点数。有位图时校验“位图有效点数 == 第 5 段打包值个数 == 实际解包值个数”；无位图（255）时校验“打包值个数 == 网格总点数”。缺测格点恢复为 `None` 并给出 `missing_reason=bitmap_missing`，不会被当作零风速。

## 缩放与坐标（全部由模板计算）

物理量按 WMO 公式还原：

```
Y = (R + X * 2^E) * 10^-D
```

其中 R 为 IEEE-754 参考值，E 为二进制缩放因子，D 为十进制缩放因子，X 为按 MSB 位序解包的无符号整数。E、D 与坐标类有符号量使用 GRIB 的“符号位+幅值”表示，不是二进制补码。

角度单位由第 3 段基本角与细分字段决定：二者为 0 时按 10^-6 度，否则按 `基本角/细分` 度。经纬度、增量、首末点均据此换算，代码不写死任何样例经纬度或比例。

## 扫描方向与稳定格点索引

扫描模式按 WMO 表 3.4 解释：

- bit1（0x80）：行内 i 方向，0 自西向东、1 自东向西；
- bit2（0x40）：列方向 j 方向，0 自北向南、1 自南向北；
- bit3（0x20）：相邻经线 i 原点交替，本实现不支持。

稳定格点索引固定为 `j*Ni + i`，其中逻辑 i=0 在最西、j=0 在最北，与扫描方向无关。采集时先把扫描序位置 k 反演为逻辑 (i,j)，再以网格西北角为锚点、按增量计算物理坐标。因此同一张网格无论正向还是反向扫描，同一稳定索引上的经纬度、值与缺测状态完全一致。端点经纬度与“首点 + 带方向增量 ×(N-1)”交叉校验，不一致即拒绝。

## 时间语义

- 起报时间（reference time）来自第 1 段，单独保存；
- 预报时效由第 4 段时间单位（表 4.4）与预报时间值给出，单位与数值分别保存；
- 有效时间 = 起报时间 + 预报时效，支持分、时、秒、日、3/6/12 小时、月、年单位。

同一有效时刻但起报时间不同的批次，`identity_key` 不同，作为独立场保存，不是重复数据。

## 位图复用边界

- 指示符 254 只允许复用**同一条消息内**先前已定义的显式位图；解析状态在消息边界处全部重置，因此跨消息复用会被拒绝；
- 复用场记录 `bitmap_reused=True` 与来源位图段偏移，可追溯；
- 缺少先前位图、或 255/254 指示符附带了多余位图数据时拒绝该场。

第 3 段网格允许在同消息内省略并复用最近定义；第 4 段产品定义与第 5 段表示模板每场必备，省略即拒绝该场。

## 夹具

本地演练夹具由 `sampledata.py` 按规范字节布局生成，均为虚构业务数据，不下载任何资源：

- `sample.grib2`：3×2 网格、6 格点、5 打包值、1 个位图缺测；`invalid.grib2` 为其截断版本；
- `harbor-batch-a/b.grib2`：同一港区 4×3 网格、跨零经线（359..362E），同有效时刻不同起报批次；
- `harbor-reverse-scan.grib2`：扫描模式 0xC0 反向扫描，验证稳定索引；
- `harbor-reused-bitmap.grib2`：同消息两场，第二场以 254 复用第一场位图；
- `harbor-orphan-bitmap.grib2`：首场 254 无先前位图被拒，后随一条完好消息；
- `harbor-unsupported-template.grib2`：网格模板号改写为 3.1，验证不支持模板拒绝。

## 本地 HTTP 演练器

采用方法与原始路径作为路由键，值为按调用次数返回的响应数组，耗尽后维持最后一项。响应可定义 status、headers、text/base64、require_headers、chunk_bytes、disconnect_after。每次请求保留方法、路径、头与正文摘要表示，便于核对实际访问；演练器只监听回环地址。

原始输入上限 16 MiB 是查看入口的保护值，不代表持续采集需一次读完整来源。格式含义和截断错误不能被 HTTP 200 覆盖。
